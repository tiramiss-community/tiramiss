# Actor emoji caches (#303)

The approved scope is the existing local actor HTTP/internal tag readers and remote actor author emoji URLs exposed by existing Note HTTP/stream/posting readers. Parent #217, whole plan #114; #290 is closed. Fixed source is `8e07cf085adf7009583d234a208e30436f020e26`.

Use one process-owned, narrowly typed cache in runtime resources. Local tags read the full local Emoji map from `singlecache:localEmojis`, Redis EX1800 and memory 180000ms, using the configured Redis keyPrefix. Revive updatedAt Dates from Redis and preserve input order/duplicates/localOnly filtering at rendering. A local reader with no names bypasses the cache as pinned renderPerson does. Remote author URL lookup uses source name/host normalization and memory 43200000ms, including null results, without invalidation by actor extraction or internal events. Preserve source strict greater-than expiry and the remote cache three-minute GC behavior. No lookup coalescing, retry, fallback, or new writes/events.

Chosen approach is a narrow platform adapter composed into actual consumers. Copying general source cache classes adds unused APIs; retaining DB reads leaves the observed freshness/failure difference. Existing pure renderers continue to consume acquired values. Existing direct-reader fixtures can retain a default reader; normal runtime always supplies the shared cache. Note emoji prefetch and Drive author readers remain outside this actor slice; they must not silently gain different cache behavior.

Pending lookups drain before resource release; the remote GC timer stops on close. No emoji management CRUD, new dependency, migration, API schema, package/entrypoint change, or whole user cache. Preserve historical receipt bytes with one finite source/current projection and scope-aware validation; package dependency projection is owned by #572. #176/#127/#195 and posting partial remain unchanged.

Real Redis/PG/listening HTTP cover warm hits under an unavailable emoji table, memory/Redis expiry, updates/deletion/negative entries, and stale URLs after actual extraction. Process tests prove active read drain and timer release.
