## Measured source contract

The GET routes `/users/:user/followers` and `/users/:user/following` run the same sequence with opposite relation ends. Before route CORS or federation access, malformed raw path percent escapes/UTF-8 return 400 with no repository calls. Decode the raw user component exactly once: `%61lice` addresses alice; double-encoded escapes stay literal after that one decode and query that ID. After successful path decoding, federation `none` returns 403 first. Next, a non-null cursor whose parsed value is not a string returns 400, including on the index; `page` selects a page only when it is exactly the string `true`. The local user lookup requires `host IS NULL`; absent user returns 404. Profile lookup uses `findOneByOrFail`; private and followers-only visibility both return 403 and `Cache-Control: public, max-age=30`. Preserve this ordering and errors, including a missing profile.

Index uses the saved `followersCount` or `followingCount`, independent of relation count, with `OrderedCollection`, `first` set to `?page=true`, and `Cache-Control: public, max-age=180`. Page fetches rows by followee or follower respectively, descending relation ID, with `id < cursor` only when cursor is truthy, `take: 11`. When exactly 11 rows are returned, remove the last and construct `next` from the last retained row; return at most 10. Page `id` uses source `url.query` encoding of page and cursor (including empty cursor; undefined is omitted), `partOf`, saved count, and `orderedItems`; no `prev` is supplied. Page paths do not explicitly set cache control. Literal query strings were injected through real Fastify: repeated cursor becomes an array and returns 400 even on index; repeated page becomes an array and selects index. Bracket keys such as cursor[] do not supply cursor. Empty cursor is preserved in page id but does not filter rows. The verified default parser is fast-querystring 1.1.2 with fast-decode-uri-component 1.0.1: split pairs on `&`, split key/value at the first `=`, replace `+` with space, then decode each entire component, retaining it on malformed percent/UTF-8. Encoded keys participate in repetition; bracket/plus/invalid keys do not become cursor/page. For `cursor=r%30z%`, preserve query cursor `r%30z%` and page ID cursor `r%2530z%25`. P2 observes this and malformed UTF-8 in both directions, alongside valid `%25`, Unicode and plus controls.

`renderFollowUser` looks up each referenced user with `findOneByOrFail` and returns `getUserUri`: local users use `${config.url}/users/${id}`, remote users use their stored URI. Preserve ordering, missing-reference failure and observed remote null behavior (a null orderedItems entry); do not filter missing entries or use an activity renderer. There are no collection writes in these methods; existing Meta initialization is a separate permitted side effect.

`addContext`, URI projection, collection renderers and `setResponseType` execute as literal source methods. Negotiation selects LD JSON if preferred and activity JSON otherwise, including HTML/absent Accept on these unconstrained routes. GET and HEAD receive the plugin CORS headers with no Vary; HEAD performs the same reads but has no body. OPTIONS has no upstream handler: it returns the Fastify 404 fallback, JSON content type, no collection CORS headers, and no repository reads. The product implements that narrow fallback explicitly; full Fastify diagnostic message strings are outside comparison.

Source execution confirmed the preliminary count/paging/visibility contract. It resolved the previously unverified query/HEAD/OPTIONS/header behavior above; it did not establish PostgreSQL collation, full-server global hooks or Meta notification timing. Source repository doubles use JS string comparisons; integration compares every observed non-ID cursor against independent PostgreSQL queries, using the literal-source relation cursor rather than a second forgiving query parser or the product helper. Source observations remain independent of the product.
