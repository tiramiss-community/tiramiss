# 基本投稿作成と独自transport撤去の実装計画

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Independent whole-branch review follows implementation and repeats until findings converge, as requested by the user.

**Goal:** 基本text投稿を通常HTTPから保存・応答まで通し、不要な独自queue transport/復旧実装を撤去する。

**Architecture:** Note作成UseCaseは取得済みのplain factsと保存窓口を使う。HTTPはJSON/credential解釈とエラー変換、DB adapterはTypeORM CRUD、compositionはRole資料/通常rate limiter/後続count更新と既存pure rendererを接続する。

**Tech Stack:** Hono / TypeORM / InversifyJS composition / PostgreSQL / Redis / upstreamと同版のratelimiter・RE2・mfm-js。

**Spec:** [最小契約](../../backend-next/posting-contract.md)、[GOALS](../../backend-next/GOALS.md)。

## Global Constraints

- 固定本家SHAは8e07cf085adf7009583d234a208e30436f020e26。旧backendとmanaged upstreamは手編集しない。
- 普通のCRUDはRepository/QueryBuilder。独自PG依頼、容量制御、全損復旧、万能dispatcherを足さない。

- production以外は本家同様rate無効。停止/移行/scope/入力より先にrateを判定する。

## Review Focus

- App permissionがAccessToken.permissionより優先され、Bearer不正時に本文tokenへfallbackしない。
- CWがあるときsensitiveWordsはCWのみ、禁止語はCWと本文を結合して検査する。
- 未対応の関連入力/MFM抽出を黙って捨ててNoteを作らない。
- 保存失敗/後続失敗/並行作成/切断を区別し、保存済みNoteやcountを二重作成しない。
- 削減後も旧migrationと残存adapterの型・schema検査を維持し、全撤去済みと誤記しない。
