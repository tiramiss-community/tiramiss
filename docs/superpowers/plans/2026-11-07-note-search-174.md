# 投稿の検索登録・削除連携 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** #174/#172の投稿作成・削除を、本家相当のMeilisearch登録・解除へ接続する。

**Architecture:** 設定・検索SDKと接続の所有はplatform/compositionに置き、登録可否とdocument変換は取得済みの投稿情報から判断する。既存の保存後処理と削除直前の境界へ狭いportを追加し、HTTP成功を検索taskの完了待ちにしない。受理済みの検索リクエストは既存の終了待機へ接続する。

**Tech Stack:** TypeScript / Hono / TypeORM / Meilisearch SDK / Vitest、実PostgreSQL・Redis・Meilisearchによる検証。

**Spec:** [GOALS](../../backend-next/GOALS.md)、[投稿の最小契約](../../backend-next/posting-contract.md)、Issue #174/#172、固定本家 `8e07cf085adf7009583d234a208e30436f020e26` の SearchService / NoteCreateService / NoteDeleteService / GlobalModule / config。

## Global Constraints

- UseCase間呼び出しを追加しない。業務コードへORM・SDK・HTTP Context・DIを公開しない。
- `fulltextSearch.provider` が `meilisearch` の場合だけ外部検索を更新する。既定SQLLikeとsqlPgroongaはNote本体を利用する。
- 固定本家の設定キー、index名、settings、index scope、document形状、ID由来時刻を比較する。
- 登録はtextまたはcwがnullでないpublic/home投稿。local/global/host allowlistの条件は固定本家どおり。
- 解除はpublic/home投稿。textとscopeの条件は解除に追加しない。DB削除開始前にリクエストを開始する。
- 本家は1投稿ずつaddDocumentsする。app側batch/flush、再試行台帳、再構築基盤を追加しない。SDK成功はtask受付であり適用完了ではない。
- 作成のpack/mention準備失敗では登録しない。既に開始したpublish/webhook/AP処理の失敗が登録を抑止しない。
- 起動・停止と失敗記録を既存の資源所有へ接続する。検索失敗で保存済みHTTP成功を失敗に変更しない。
- 検索API、antenna、hashtag更新、featured、Role TL、再構築はこのPRで完成としない。#174/#172/#176はcloseしない。
- managed upstream定義、旧backend/frontend、locale、CHANGELOGを手編集しない。

## Review Focus

1. provider未指定とMeili設定だけの組合せで外部通信が発生しない。
2. textなし/CWだけ/空文字、public/home/非公開、remote scopeと削除側の異なる条件が本家と一致する。
3. pack準備失敗とdetached副作用失敗で登録開始の境界を取り違えない。
4. DB削除失敗でも解除開始済みという本家の境界、HTTP応答と検索task受付/適用の違いを維持する。
5. 検索の初期settings失敗・通信失敗・処理中停止で未処理Promiseや接続解放後アクセスを残さない。
