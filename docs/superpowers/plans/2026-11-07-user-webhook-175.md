# User webhook posting slice implementation plan

> Execution is delegated to the current worker; review is independent before handoff.

**Goal:** Deliver posting user webhooks through the normal BullMQ worker with fixed-upstream behavior.

**Architecture:** The existing post-save event coordinator selects events and supplies its existing packed note; a narrow webhook port resolves active hooks and snapshots destination and secret in queue data. Database facts, queue transport, outbound HTTP and worker lifecycle remain in their existing platform/composition layers.

**Tech Stack:** TypeScript, TypeORM, BullMQ, Redis, PostgreSQL, Vitest.

**Spec:** [#175](https://github.com/tiramiss-community/tiramiss/issues/175), [#127](https://github.com/tiramiss-community/tiramiss/issues/127), [#197](https://github.com/tiramiss-community/tiramiss/issues/197), [posting contract](../../backend-next/posting-contract.md); fixed upstream `8e07cf085adf7009583d234a208e30436f020e26`.

## Global constraints

No old backend edits, new PG queue state, additional config or stronger delivery guarantee. Sync upstream Entity mechanically. Hook administration and nonposting events belong to #197; system hooks to #198; final cross-flow to #176. Do not depend on unmerged #230. No commit, push, PR, CHANGELOG or non-Japanese locale edit in this task.

## Review focus

1. Self mention/reply is delivered even where notification suppresses self; mute prevents mention/reply.
2. Renote self and remote recipient do not emit; quote still emits renote to another local author.
3. Enqueued URL and secret survive subsequent hook disable/update/delete.
4. HTTP 4xx except 429 stops; 429, 5xx and network failures retry with upstream backoff.
5. Shutdown drains accepted post-save work and closes worker; missing/deleted hook does not prevent queued delivery.
