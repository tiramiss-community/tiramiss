# Role HTTP API Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task; request an independent review and repeat until findings converge, as instructed by the user.

**Goal:** #120 の既存トークン認証とRole show/updateを実HTTPから利用可能にする。

**Architecture:** Honoは認証結果と入力を業務へ渡し、業務例外を固定したAPI応答へ変換する。UseCase内でサスペンド・資格・scopeを確認した後に入力を検証し、updateは同じDBトランザクションで認可・保存・監査を行う。showは取得と人数集計を先に終え、純粋なHTTP変換へ渡す。

**Tech Stack:** TypeScript, Hono, TypeORM/PostgreSQL, Redis, Ajv 8.20.0, Node crypto, ulid 3.0.2.

**Spec:** `docs/superpowers/specs/2026-10-17-role-compatibility-contract.md`、Role詳細設計、基本設計。既に合意済みの設計を具体化し、自律実装・PRの指示に従って進める。

## Global Constraints

- 本家固定SHA `8e07cf085adf7009583d234a208e30436f020e26`。旧backend・managed upstreamコピーは変更しない。
- HTTP/ORM/APIエラー型を業務へ渡さず、UseCase間呼び出しを加えない。
- native16文字・AccessToken hash/token・App scope、拒否順を維持する。
- update成功は204空本文。切断で取消・送信失敗で再実行しない。
- 既存設定のID方式6種類をcompositionから接続する。材料キャッシュの保証を維持する。
- infraは専用Compose `role-120-test`、DB55120・Redis56120のみ。

## Review Focus

- 誤ったBearerと正しい本文トークンの組合せでもBearerの失敗を返す。
- 資格なし・scopeなしと不正入力の同時発生時に認可拒否を先に返す。
- 更新後に保存データと監査を一回だけ確定し、クライアント切断でも処理を継続する。
- 全ID方式でRole作成日時と監査IDを既存DB互換の形式へ変換する。
- 未知トップレベル入力を保存せず、任意のJSON内容・省略/nullを正規化しない。

## 実行結果（2026-10-21）

- 通常のcheckout上の専用ブランチ `feat/backend-next-role-http-120`、base `aec0f6ff97` で実装。開始時の単体130件はPASS。
- UseCaseの更新引数はroleId/patchから未検証入力objectへまとめた。認可後検証の順序を維持し、HTTP型・HTTPエラーを業務へ渡さないための具体化で、保存項目や成立条件は変えていない。
- 本家が待たないAccessToken使用日時更新は、終了時に未追跡のDB操作を残さないためawaitする。ただし使用日時の更新失敗だけでは認証/業務結果を変えない。
- 独立レビュー初回で本文1 MiB上限の欠落と認可前の深い未知JSONの複製失敗を指摘。実TCP回帰テストでそれぞれ204/500のREDを確認し、413/正しい認可・成功応答のGREENへ修正した。超過応答は未読本文のある接続を再利用しないためConnection:close。
- 既知フィールドのコピーを非同期認可前に保持し、コピーエラーは認可後の入力検証より後に伝える。未知フィールドは複製しない。通常の入力変更隔離は単体テストで確認した。
- 独立再レビューで未解消Critical/Important/Minorは0件。レビュアーは関連単体34件・実TCP HTTP結合57件を独立実行してPASS。
- 最終のbuild/typecheck、sync:check、単体158件・結合95件・起動停止20件はPASS。出荷時のlint/SPDX/localeは比較資料の最終記録を参照。
- multipart等の全プロトコル互換性と#121の総合比較・障害受け入れは対象外。旧backend API定義・schema・managed同期対象に変更はない。
