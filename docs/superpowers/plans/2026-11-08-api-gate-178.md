# API common gate first slice (#178) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace per-API token handling, per-permission booleans and the Role-specific error mapper with one shared API gate, and move the Role and queue administration APIs onto it.

**Architecture:** The gate is split by responsibility instead of being one HTTP middleware. HTTP owns the request envelope: route guards, body parse, token extraction, authentication, response and error rendering. A new pure `access` module owns the credential, its permission set, the ordered authorization check and the common error types. UseCases call that check with fresh facts, so `roles/update` keeps authorizing inside its transaction. Platform owns the authenticator and a shared rate limiter with upstream `RateLimiterService` semantics.

**Tech Stack:** Hono, TypeORM, ioredis + `ratelimiter`, Ajv 8, Vitest. No new dependency, schema, migration or setting.

**Spec:** [GOALS](../../backend-next/GOALS.md), [ROADMAP](../../backend-next/ROADMAP.md), [#178](https://github.com/tiramiss-community/tiramiss/issues/178), parent [#128](https://github.com/tiramiss-community/tiramiss/issues/128), overall [#114](https://github.com/tiramiss-community/tiramiss/issues/114). ## Upstream gate contract (order)

1. Route: CORS `*` and `Cache-Control: private, max-age=0, must-revalidate` on every API route, including 405/413/errors. Body over 1 MiB gives 413. GET without `allowGet` gives 405 before authentication. Other methods are accepted.
2. Token: a case-sensitive `Authorization: Bearer ` header wins, else `body.i`. `i` stays in the input.
3. Authenticate: `token == null` is anonymous. A 16-character token is native (all permissions). Otherwise an access token by `hash = lower(token)` or `token`; the App's permission wins when `appId` is set. A failure gives 401 `AUTHENTICATION_FAILED` with `invalid_token`. Other errors at this stage give a bare 500 `INTERNAL_ERROR` without `info`. An invalid token fails even where no credential is required.
4. Rate limit (endpoints with `limit`): actor = user id; factor = max role `rateLimitFactor`; production only; `:min` window first; 429 with `info` and `Retry-After`.
5. Credential required: no user gives 401 `CREDENTIAL_REQUIRED` with exactly `Bearer realm="Misskey"`. Suspended gives 403.
6. `prohibitMoved` gives 403 `YOUR_ACCOUNT_MOVED`.
7. Role (root bypasses): moderator `d33d5333`, administrator `c3d38592`, both 403 `ROLE_PERMISSION_DENIED`.
8. Scope (non-native only): the endpoint `kind` must be in the permission set; a credentialed endpoint without `kind` denies every non-native token. 403 `PERMISSION_DENIED` with `insufficient_scope`.
9. Ajv (`useDefaults`, `misskey:id`): 400 `INVALID_PARAM` with `info {param: schemaPath, reason: message}`.
10. Response: `undefined`/`null` gives 204, otherwise JSON. Errors are `{error: {message, code, id, kind, info?}}`. Status/header precedence: 401 plain realm; `RATE_LIMIT_EXCEEDED` adds `Retry-After`; kind `client` defaults to 400 with `invalid_request`; kind `permission` defaults to 403, only `PERMISSION_DENIED` adds `insufficient_scope`. An unexpected handler error gives 500 `INTERNAL_ERROR` with `info.e {message, code: name, id}` and a log entry.

## Review Focus

- Role before scope, suspension before role, credential before everything, and authorization before input validation must hold for Role and queue (pinned by `role-http` and `queue-admin` tests and upstream `test/e2e/api.ts:157-175`).
- A native token skips scope; an App's permission overrides the token's; a token for a credentialed endpoint without `kind` is denied.
- `roles/update` still reads facts and authorizes inside the same transaction; a revoked administrator is rejected even with a warm cache.
- Authentication-stage 500 stays bare; handler-stage 500 carries `info.e`. Detached queue work still drains.
- Streaming keeps its own contract: an App token without `read:account` is 401 `invalid_token` "Failed to authenticate", not 403.

## File Structure and Interfaces

New `src/modules/access/`:

- `credential.ts`: `AccessCredential = { userId; native: true } | { userId; native: false; permissions: ReadonlySet<string> }`, `allowsPermission(credential, permission)`.
- `errors.ts`: `AccessDenied(reason)` with reasons `CREDENTIAL_REQUIRED | YOUR_ACCOUNT_SUSPENDED | MODERATOR_REQUIRED | ADMINISTRATOR_REQUIRED | PERMISSION_DENIED` (`YOUR_ACCOUNT_MOVED` arrives with the note slice), `AuthenticationFailed`, `InputInvalid(param, reason)`.
- `authorize.ts`: `AccessRequirement { requireCredential?, requireModerator?, requireAdmin?, kind? }`, `AccessFacts { isSuspended, isModerator, isAdministrator }` (root folded into both role facts), `requireCredential(credential)`, `authorizeAccess(requirement, credential, facts)` (facts are mandatory with a credential), and `createAccessRequest(requirement, credential)`: an `AccessRequest { credential, authorize(facts) }` bound to the endpoint requirement that records whether `authorize` ran. `prohibitMoved` arrives with the note slice, its first user.
- `input.ts`: `compileInput(schema)` on one shared Ajv (`useDefaults`, `misskey:id`) throwing `InputInvalid`.
- `public.ts`.

HTTP:

- `src/http/api-error.ts` (rewritten): `ApiErrorBody`, `apiErrorResponse(body)` applying the upstream status/header precedence, `commonApiError(error)` for `AccessDenied`/`AuthenticationFailed`/`InputInvalid`, and the `INTERNAL_ERROR`/`AUTHENTICATION_FAILED` bodies. The gate builds the bare authentication-stage 500 and the handler-stage 500 with `info.e`.
- `src/http/api-request.ts`: `registerApiRoute(app, path, handler)` (CORS, Cache-Control and the body limit on the exact path) and `readApiRequest(context)` returning `{ input, token }` or an empty 405/400 response.
- `src/http/api-endpoint.ts`: `createApiEndpoints({ endpoints, authenticate, logger })` returning a Hono app. `ApiEndpoint { name; access; handle(access: AccessRequest, input); errors?(error) }`. The gate rejects a guest of a credentialed endpoint before the UseCase, and turns a successful handler that never called `authorize` into an internal error. CORS, Cache-Control and the body limit are registered per exact endpoint path so merged sub-apps (actor routes, note routes) are unaffected.
- `src/http/role-api.ts`, `src/http/queue-api.ts`: endpoint definitions only.
- Remove `src/http/authentication-error.ts` and `src/http/input-error.ts`. Note handlers keep their tables and authorization but use `registerApiRoute`, `readApiRequest`, `apiErrorResponse` and `commonApiError`.

Platform:

- `src/platform/database/authenticate.ts`: returns `{ credential: AccessCredential; isSuspended: boolean } | null`.
- `src/platform/database/streaming.ts`: adapts to the existing `{ userId, canReadAccount, isSuspended }` port.
- `src/platform/api-rate-limit.ts`: `createApiRateLimiter(redis)` with `{ key, duration, max, minInterval? }`; note limiters wrap it.

UseCases: Role and queue take an `AccessRequest`; Role keeps `prepareRoleInput` (snapshot before the first await), then reads fresh facts and calls `access.authorize`, `roles/update` inside its transaction; only the Ajv instance and `RoleInputInvalid` change to `compileInput`/`InputInvalid`. Fact readers throw `access.AuthenticationFailed` for a vanished user. Note create/delete check `allowsPermission(credential, 'write:notes')`. `docs/superpowers/compatibility/api-common/endpoint-access.json` pins the upstream meta of every registered endpoint (generated by `reference-endpoint-access.mjs`).
